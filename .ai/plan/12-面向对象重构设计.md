# flexui-rs 面向对象重构设计（参考 duilib WinImplBase/Window）

> **状态：已实现（2026-08-07）**。决策 Q1=组合式+能力 trait、Q2=移除 run/run_xml 统一 OO。
> 已落地：`WindowImpl`(≈WindowImplBase) + `Window`(≈Window) + `WindowCtx`/`Skin`/`WindowDelegate`
> + `WindowHandle`（双平台）；能力 trait `TextControl/Clickable/Container`；
> `Dispatcher::take_activations`。示例全部迁移到 OO；host/windows clippy 0，20 测试通过，
> macOS 运行 + wine 存活验证。

目标：把现在「函数式」的 `run(config, root, disp)` / `run_xml(...)` 改成 duilib 风格的
**面向对象**用法——用户「继承」一个窗口基类、重写钩子，控件有清晰的类型层级。

## 1. duilib 的 OO 模型（现状参照）
- 窗口：`Window`(CWindowWnd, HWND 封装 + Create/Close/ShowWindow/CenterWindow/HandleMessage 虚)
  → `WindowImplBase : Window, IUIMessageFilter`：
  - 纯虚（必须重写）：`GetSkinFolder()`、`GetSkinFile()`、`GetWindowClassName()`
  - 虚钩子（可重写）：`InitWindow()`、`CreateControl()`、`Notify()`、`OnClose/OnSize/OnChar/OnNcHitTest/OnMouseWheel/OnDpiChanged/...`
  - `GetSkinFile()` 返回 XML → 基类自动加载并 build 控件树
- 控件：`PlaceHolder→Control→Box`，模板链 `Label→Button→CheckBox→Option(Radio)`。

## 2. Rust 映射策略（核心思想）
Rust 无类继承。两种「基类的虚方法」的地道替代：
- **窗口 → trait + 默认方法**：`trait WindowImpl` 就是 `WindowImplBase`，required 方法=纯虚，
  provided 默认方法=可重写虚钩子。**这是最贴切、最地道的映射**。
- **控件 → 组合式基类**（现状）：每个控件内嵌 `Base` + 实现 `Widget` trait，
  等价 C++「基类字段 + 虚方法」。Rust 官方立场是「组合优于继承」。

## 3. 窗口 OO 层（本次重构主体）

### 3.1 `WindowImpl` ≈ `WindowImplBase`（用户"继承"它）
```rust
pub trait WindowImpl: 'static {
    // —— 必需（≈ 纯虚）——
    fn config(&self) -> WindowConfig;   // 标题/宽高/resizable/边框/标题栏模式
    fn skin(&self) -> Skin;             // Skin::xml(字符串) 或 Skin::res("main.xml")(资源系统落地后)

    // —— 可重写钩子（≈ 虚，带默认实现）——
    fn on_init(&mut self, ctx: &mut WindowCtx) {}          // ≈ InitWindow：绑事件/取控件
    fn on_click(&mut self, name: &str, ctx: &mut WindowCtx) {} // ≈ Notify：统一点击通知
    fn on_close(&mut self, ctx: &mut WindowCtx) -> bool { true } // 返回是否允许关闭
    fn on_size(&mut self, w: f32, h: f32, ctx: &mut WindowCtx) {}
    fn on_key(&mut self, key: u32, ctx: &mut WindowCtx) {}
    fn create_control(&mut self, class: &str) -> Option<Node> { None } // ≈ CreateControl：自定义控件
    // 逃生舱：需要原生消息时（可选）
}
```

### 3.2 `Window` ≈ `Window`(驱动，用户不继承直接用)
```rust
pub struct Window { /* 平台窗口 + Box<dyn WindowImpl> + 控件树 + Dispatcher */ }
impl Window {
    pub fn new(imp: impl WindowImpl) -> Self;
    pub fn center(self) -> Self;
    pub fn run(self);            // 建原生窗 → 加载 skin → on_init → 进消息循环
}
```

### 3.3 `WindowCtx` ≈ FindControl + 窗口控制 API（传给钩子）
```rust
pub struct WindowCtx<'a> { /* &mut 控件树 + &dyn WindowHandle */ }
impl WindowCtx<'_> {
    // 控件访问（复用现有 EventCtx 能力）
    pub fn set_text(&mut self, name: &str, s: impl Into<String>);
    pub fn is_selected(&mut self, name: &str) -> Option<bool>;
    pub fn set_enabled(&mut self, name: &str, on: bool);
    pub fn with<R>(&mut self, name: &str, f: impl FnOnce(&mut dyn Widget) -> R) -> Option<R>;
    // 窗口控制（≈ Window::Close/ShowWindow/...）
    pub fn set_title(&mut self, s: &str);
    pub fn close(&mut self);
    pub fn minimize(&mut self);
    pub fn maximize(&mut self);
    pub fn restore(&mut self);
}
```

### 3.4 用户用法（≈ `class MainWindow : public WindowImplBase`）
```rust
struct MainWindow { count: u32 }
impl WindowImpl for MainWindow {
    fn config(&self) -> WindowConfig { WindowConfig { title:"Demo".into(), width:680.,height:560., ..Default::default() } }
    fn skin(&self) -> Skin { Skin::xml(include_str!("assets/showcase.xml")) }
    fn on_init(&mut self, ctx: &mut WindowCtx) { /* 可预设文本等 */ }
    fn on_click(&mut self, name: &str, ctx: &mut WindowCtx) {
        match name {
            "btnPrimary" => { self.count += 1; ctx.set_text("status", format!("点击 {} 次", self.count)); }
            "btnClose"   => ctx.close(),
            _ => {}
        }
    }
    fn on_close(&mut self, _ctx: &mut WindowCtx) -> bool { true }
}
fn main() { Window::new(MainWindow{ count:0 }).center().run(); }
```

对照 duilib：`WindowImpl`↔`WindowImplBase`、`Window`↔`Window`、`on_click`↔`Notify`、
`config/skin`↔`GetSkinFile/GetWindowClassName`、`WindowCtx`↔`FindControl+窗口API`。

### 3.5 事件如何回到 on_click（Notify 机制）
- `Dispatcher` 增加「本次激活的控件」记录：`take_activations() -> Vec<WidgetId>`。
- `Window` 驱动在每次分发后，把激活控件的 `name` 取出，逐个调 `imp.on_click(name, ctx)`。
- 这样 core 不依赖 WindowImpl；同时**保留**现有「控件级 `on_click` 闭包」两种风格并存。

## 4. 控件层的「继承」怎么表达（关键分叉，见文末问题）
- **方案 A（推荐）**：保持组合式 `Base + Widget`，另加一组**标记 trait** 表达层级
  （`trait TextControl: Widget`、`trait Clickable: Widget`），并在文档里画出
  「Label/Button/CheckBox/Radio 的能力继承视图」。改动小、Rust 地道。
- **方案 B**：把控件改成 `Deref` 继承链（`Button{ label: Label }` + `Deref<Target=Label>`，
  依此叠 CheckBox/Radio）。更像 duilib，但 `Deref` 冒充继承在 Rust 是公认反模式，
  与 `Widget` trait 对象叠加时易出借用/类型坑，收益低。

## 5. 影响面
- 新增 `flexui-core`：`WindowImpl`/`WindowCtx`/`Skin` 抽象、`Dispatcher::take_activations`。
- 两后端 `run` 改为由 `Window` 驱动调用（保留内部实现，换外壳）。
- facade：导出 `Window`/`WindowImpl`/`WindowCtx`/`Skin`；旧 `run/run_xml` 视决策保留或移除。
- 迁移示例到 OO 用法。
