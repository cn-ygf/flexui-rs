# flexui-rs 资源管理设计

对应新需求：
- RM1：API 设置资源路径，XML/图片/字体/任意文件都经 API 读取（类 duilib）。
- RM2：资源可打包成**带密码的压缩包**。
- RM3：支持压缩包**内嵌**（编进二进制）。
- RM4：统一抽象接口，使用者方便。
- RM5：XML 里引用的路径走上述抽象路径。

## 1. 核心抽象

新增 crate `flexui-resource`（L2/L3，平台无关）。核心是「按逻辑路径拿字节」：

```rust
/// 资源提供者：把逻辑路径解析成字节。
pub trait ResourceProvider: Send + Sync {
    fn read(&self, path: &str) -> Result<Vec<u8>, ResError>;
    fn exists(&self, path: &str) -> bool;
}

/// 资源管理器：可叠多个 provider（先命中者优先），并做路径规范化。
pub struct ResourceManager {
    providers: Vec<Box<dyn ResourceProvider>>,
}
impl ResourceManager {
    pub fn read(&self, path: &str) -> Result<Vec<u8>, ResError>;
    pub fn read_string(&self, path: &str) -> Result<String, ResError>;
    pub fn mount(&mut self, p: impl ResourceProvider + 'static); // 追加一层
}
```

**逻辑路径**：一律相对、正斜杠，如 `skin/main.xml`、`img/btn.png`。规范化去掉 `./`、
拒绝 `..` 越权。可选统一前缀 `res://`（XML 里写 `res://img/btn.png` 或直接 `img/btn.png`）。

## 2. 三种 Provider（对应 RM1/RM2/RM3）

| Provider | 说明 | 依赖 |
| -------- | ---- | ---- |
| `DirProvider{ base }` | 从文件系统某目录读（RM1，类 duilib `SetResourcePath`） | 无 |
| `ZipProvider{ archive, password }` | 从**带密码 zip** 读（RM2） | zip 库 |
| `EmbeddedProvider` | `include_bytes!` 内嵌的 zip 字节，内存游标读（RM3） | zip 库 |

`ZipProvider`/`EmbeddedProvider` 共用同一套 zip 解码，只是数据来源不同（文件 vs `&'static [u8]`）。

### 依赖说明（R2 约束）
zip 是压缩库、非渲染/窗口框架，符合「不依赖第三方渲染库/窗口管理器」。建议用
`zip` crate（`aes-crypto` feature 支持 AES 加密；ZipCrypto 也支持）。若坚持零依赖，
可自实现「简单 AES-CTR + 索引」的自定义容器（成本高，列为可选）。**建议用 zip crate**。

## 3. 使用者 API（RM4）

App/Window 级持有一个 `ResourceManager`，暴露简单入口：

```rust
// 目录
app.resources().mount(DirProvider::new("assets"));
// 带密码 zip
app.resources().mount(ZipProvider::open("skin.dat", "p@ss")?);
// 内嵌 zip
static SKIN: &[u8] = include_bytes!("../assets/skin.zip");
app.resources().mount(EmbeddedProvider::new(SKIN, "p@ss"));

// 任意文件
let bytes = app.resources().read("data/config.json")?;
```

叠层顺序 = 覆盖优先级（例如先挂开发目录覆盖、再挂内嵌包兜底），便于换肤/热更。

## 4. 与各子系统打通

### 4.1 XML（RM5）
- 新入口 `load_xml_res(res: &ResourceManager, path: &str, ctx) -> LoadResult`：
  经 provider 读 XML 字节再解析。
- `<Include src="...">`、`<Image src="...">`、`*-bgimage/*-fgimage` 属性里的路径
  全部是**逻辑路径**，构建时经同一 `ResourceManager` 解析。

### 4.2 图片（关键改造）
现状 `ImageSource::Path(String)` → 后端直接按文件路径加载。要支持 zip/内嵌，必须
**从字节加载图片**：
```rust
pub enum ImageSource {
    Path(String),          // 文件系统直读（保留）
    Res(String),           // 逻辑路径，经 ResourceManager 解析成字节
    Bytes(Arc<[u8]>),      // 直接字节
}
```
- 后端新增「从内存字节解码图片」：macOS `NSImage(data:)`；Windows `GdipCreateBitmapFromStream`/
  `GdipLoadImageFromStream`（IStream over memory）或先落临时文件（下策）。
- **解码缓存**：按 source 缓存已解码句柄（避免每帧重解码）；资源管理器或后端持有 LRU 缓存。

### 4.3 字体（RM1 "字体"）
- 自定义字体文件从资源加载后需向系统注册：macOS `CTFontManagerRegisterGraphicsFont`/
  从 data 创建；Windows GDI+ `PrivateFontCollection::AddMemoryFont` 或 `AddFontMemResourceEx`。
- `Font { family, size }` 增加「来自资源的字体名」解析。列 P1（不阻塞主流程）。

## 5. 分层与依赖方向
```
flexui-resource (ResourceProvider/Manager, zip)  ← 平台无关
   ↑ 被 flexui-xml（读 XML/Include）、flexui-core（图片字节）、后端（图片/字体解码）使用
```
`ResourceManager` 由 App 持有并注入到 XML 加载与绘制路径。

## 6. 待确认决策
- D-RM1：压缩包用 `zip` crate（含 AES）还是自实现容器？**建议 zip crate**。
- D-RM2：图片是否引入解码缓存（LRU）？**建议是**（否则每帧重解码卡顿）。
- D-RM3：逻辑路径前缀是否强制 `res://`？**建议不强制**，裸相对路径即可，`res://` 可选。
