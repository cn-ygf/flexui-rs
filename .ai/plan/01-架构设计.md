# flexui-rs 架构设计

> **历史设计基线**：当前已加入 Linux 后端并扩展公共 API，最新进度以 `14-当前进度与下一阶段.md` 为准。

## 1. 分层原则

遵循 AI_RULES「代码分层拆分复用」。核心思想：**平台差异只存在于最底层，越往上越平台无关**。
上层控件/布局代码完全不感知 macOS 还是 Windows。

```
┌─────────────────────────────────────────────┐
│  L6  FFI 层（C ABI）  flexui-ffi（cdylib）      │  ← 未来给别的语言用
├─────────────────────────────────────────────┤
│  L5  公共 API 层     App / Window / Widget      │  ← 用户写这一层
├─────────────────────────────────────────────┤
│  L4  控件层          Label/Button/Stack…        │  平台无关
├─────────────────────────────────────────────┤
│  L3  布局层(Flex) + 事件分发 + 命中测试          │  平台无关
├─────────────────────────────────────────────┤
│  L2  绘图抽象层  Canvas trait + 几何/颜色/字体    │  平台无关接口
├─────────────────────────────────────────────┤
│  L1  平台后端层  Backend/Window/Canvas 实现       │  ← 唯一含平台代码 & unsafe
│      macOS(AppKit+CoreGraphics) / Win(Win32+GDI+)│
└─────────────────────────────────────────────┘
```

**依赖方向**：只能自上而下。L3/L4 依赖 L2 的 **trait**，不依赖具体后端；
后端由 L5 在启动时按 `cfg(target_os)` 选定并注入。

## 2. Crate / 模块划分（Cargo workspace）

采用 workspace 多 crate，边界清晰、便于复用与独立测试：

| Crate | 层 | 职责 | 平台相关 |
| ----- | -- | ---- | -------- |
| `flexui-geometry` | L2 | Point/Size/Rect/Insets/Transform/Color 等值类型 | 否 |
| `flexui-gfx` | L2 | `Canvas` 绘图 trait、绘图原语、`Font`/`TextLayout` 接口 | 否（仅接口） |
| `flexui-core` | L3/L4 | 事件枚举、控件 trait、控件树、状态机/样式、Flex 布局、命中测试、脏区、Radio/TabBox、Platform 谓词 | 否 |
| `flexui-xml` | L4/L5 | XML 布局解析、v-if 求值、属性→控件映射（类 duilib） | 否 |
| `flexui-macos` | L1 | AppKit + CoreGraphics 后端 | 仅 macOS 编译 |
| `flexui-windows` | L1 | Win32 + GDI+ 后端 | 仅 Windows 编译 |
| `flexui` | L5 | 门面 crate：按 cfg 选后端 + 公共 API 再导出 | 条件依赖 |
| `flexui-ffi` | L6 | C ABI 封装，产出 `cdylib` + 头文件 | 否（转调 L5） |

> 简化选项：一期也可先做单 crate + 模块（`platform/macos`、`platform/windows`），
> 待接口稳定再拆 workspace。**建议直接用 workspace**，避免后期大改依赖。

## 3. 核心抽象（trait 草案）

平台后端需实现三组核心 trait（放在 `flexui-gfx` / `flexui-core`）：

```rust
/// 后端总入口：负责应用/事件循环的启动与窗口创建。
pub trait Backend {
    type Window: PlatformWindow;
    fn init() -> Self;                       // GdiplusStartup / NSApplication 初始化
    fn create_window(&self, cfg: WindowConfig) -> Self::Window;
    fn run(self, handler: impl EventHandler); // 进入主消息循环 / [NSApp run]
}

/// 平台窗口：控制原生窗口，并在需要重绘时给出画布。
pub trait PlatformWindow {
    fn set_title(&self, s: &str);
    fn request_redraw(&self, dirty: Option<Rect>); // setNeedsDisplay / InvalidateRect
    fn scale_factor(&self) -> f32;                 // HiDPI
    // drawRect / WM_PAINT 时回调上层，提供 Canvas
}

/// 画布：所有自绘控件面向它编程，双后端各自实现。
pub trait Canvas {
    fn fill_rect(&mut self, r: Rect, color: Color);
    fn stroke_rect(&mut self, r: Rect, color: Color, width: f32);
    fn fill_round_rect(&mut self, r: Rect, radius: f32, color: Color);
    fn draw_path(&mut self, path: &Path, paint: &Paint);
    fn draw_text(&mut self, text: &str, at: Point, font: &Font, color: Color);
    fn measure_text(&self, text: &str, font: &Font) -> Size;
    fn push_clip(&mut self, r: Rect);
    fn pop_clip(&mut self);
    // 变换 / 透明度 等按需扩展
}
```

上层控件只依赖 `Canvas` / `Event`，与平台彻底解耦。

## 4. 控件与渲染模型

- **保留模式**：内存中维护一棵**控件树**（widget tree）。
- **控件 trait**：`layout()` 求尺寸/位置、`paint(&Canvas)` 自绘、`on_event(Event)` 处理事件。
- **状态机 + 样式**：每个控件带 4 基础态（Normal/Hot/Pushed/Disabled）× focus = 8 个样式槽，
  每槽可配 背景/前景图、背景/前景色、边框色/宽、圆角、rect；解析走「状态优先级 + 字段级回退到
  Normal」。详见 `06-控件与样式模型.md`。
- **容器模型**：所有控件是单子容器（0..1 子）；`Box/VBox/HBox` 为多子容器。
- **命中测试策略**：控件可设 `Solid`（消费事件）或 `Transparent`（穿透）。
- **脏区失效**：状态变更 → 标记控件 dirty → 合并脏矩形 → 通知平台窗口
  `request_redraw(dirty)` → 平台回调 → 只重绘脏区。
- **Windows 双缓冲**：GDI+ 直接画到窗口会闪烁，需**先画到内存位图再 BitBlt**；
  macOS 的 layer-backed view 已自带缓冲。此差异封装在后端内，上层无感。

### 4.1 控件树的两种构建入口
代码 Builder 与 XML 加载器最终产出**同一棵控件树**：Builder 是「属性 setter 集合」，
`flexui-xml` 只是把 XML 属性字符串翻译成对 Builder 的调用（含 `v-if` 静态求值 + 平台谓词），
不重复实现控件逻辑。详见 `07-布局与XML.md`。

## 5. 事件流

```
原生事件 (NSEvent / WndProc msg)
   → 后端翻译成统一 Event 枚举
   → core 事件分发器：命中测试(hit-test) 找到目标控件
   → 冒泡/捕获路由 → 控件 on_event
   → 控件改状态 → 标记脏区 → request_redraw
```

统一事件枚举（草案）：`MouseMove/Down/Up/Wheel`、`KeyDown/Up/Char`、
`Focus/Blur`、`WindowResized/CloseRequested/ScaleChanged`。

## 6. 坐标与单位

- 统一使用**逻辑像素（点）** + 左上原点、y 向下。
- macOS 默认左下原点、y 向上 → 后端做 **Y 翻转**。
- HiDPI：逻辑坐标 × `scale_factor` = 物理像素；缩放在后端绘制时统一处理。

## 7. 线程模型

- 一期：**单线程**，UI 全部在主线程（两平台强制要求）。
- 跨线程通信（如后台任务回主线程刷新）预留一个「事件注入 / 唤醒主循环」的接口
  （macOS `performSelectorOnMainThread`/自定义 source，Windows `PostMessage`），
  但一期不铺开实现。

## 8. 错误与 unsafe 收敛

- 所有 `unsafe`、objc 消息、Win32 调用只出现在 L1 后端 crate。
- 后端把系统失败转成 `Result<_, PlatformError>`，上层拿到的是安全类型。
- FFI 边界（L6）用 `catch_unwind` 防止 panic 穿越 C ABI。
