# flexui-rs 平台后端设计

后端层（L1）是唯一的平台相关代码，目标：把两套完全不同的原生 API，收敛到
`01-架构设计.md` 定义的 `Backend / PlatformWindow / Canvas` 三组 trait。

## 1. 能力对照表（一图看清映射）

| 能力 | 统一抽象 | macOS (AppKit + CoreGraphics) | Windows (Win32 + GDI+) |
| ---- | -------- | ----------------------------- | ---------------------- |
| 应用初始化 | `Backend::init` | `NSApplication.sharedApplication` | `GdiplusStartup` + 注册窗口类 |
| 创建窗口 | `create_window` | `NSWindow` + 自定义 `NSView` | `CreateWindowExW` |
| 事件循环 | `Backend::run` | `[NSApp run]` / RunLoop | `GetMessage/Translate/DispatchMessage` |
| 重绘触发 | `request_redraw` | `setNeedsDisplay(_:)` | `InvalidateRect` |
| 绘制入口 | 上层 `paint(Canvas)` | `NSView.drawRect:` | `WM_PAINT` + `BeginPaint` |

| 填充/描边矩形 | `fill/stroke_rect` | `CGContextFillRect` 等 | `GdipFillRectangle` / `GdipDrawRectangle` |
| 圆角/路径 | `fill_round_rect`/`draw_path` | `CGPath` + `CGContextAddPath` | `GdipAddPath*` / `GdipCreatePath` |

## 2. macOS 后端要点

- **绑定选择**：建议用 `objc2` + `objc2-app-kit` / `objc2-foundation`（或手写 objc 运行时
  extern）。它们是**系统 API 绑定**，非渲染/窗口框架，符合「不依赖第三方渲染库/窗口管理器」。
- **自定义 NSView**：需要在运行时**子类化 NSView**，覆写 `drawRect:`、`mouseDown:`、
  `acceptsFirstResponder` 等。用 `objc2` 的 `declare_class!` 或运行时 `class_addMethod`。
  这是 macOS 后端最核心也最易踩坑的部分。
- **绘制**：`drawRect:` 内取当前 `NSGraphicsContext.CGContext`，包成我们的 `Canvas`，
  调用上层 `paint`。文字优先 **Core Text**（度量准）。
- **坐标**：默认 y 向上 → 可 `isFlipped` 返回 true 让 view 变成左上原点，简化坐标换算。
- **事件循环**：`NSApplication` + `NSApp.run()`；激活策略 `setActivationPolicy(.regular)`。
- **生命周期**：objc 对象用绑定库的智能指针（`Retained<T>`）管理 retain/release。

## 3. Windows 后端要点

- **绑定选择**：建议官方 `windows` crate（windows-rs），含 `Win32::Graphics::GdiPlus`
  的 **flat API**（`Gdip*` 函数）。同样属系统 API 绑定，符合约束。
- **窗口**：`RegisterClassW` 注册类 + `WndProc` 回调；`CreateWindowExW` 建窗；
  `WndProc` 里 `match msg` 分发到统一事件。`WndProc` 需能拿到 Rust 侧窗口对象
  （`SetWindowLongPtr(GWLP_USERDATA)` 存指针）。
- **GDI+ 初始化**：进程启动 `GdiplusStartup`，退出 `GdiplusShutdown`（RAII 包装）。
- **绘制**：`WM_PAINT` → `BeginPaint` 拿 HDC → **建内存位图 DC 双缓冲** → 用
  `GdipCreateFromHDC` 得 `Graphics` 包成 `Canvas` → 上层 `paint` → `BitBlt` 到窗口 → `EndPaint`。
  `GdipGraphicsSetSmoothingMode` 抗锯齿、`TextRenderingHint` 提升文字质量。
- **DPI**：清单或 API 声明 **Per-Monitor v2**；`WM_DPICHANGED` 更新 scale。
- **Unicode**：一律走 W 版 API，Rust `&str` ↔ UTF-16。

## 3.5 GDI+ 从 Rust 调用的注意点

GDI+ 本是 C++ 类库，Rust 只能用其 **flat C API**（`GdipXxx`），风格是
「创建句柄 → 操作 → 删除句柄」，返回 `GpStatus` 错误码。封装时：
- 每个句柄（`GpGraphics/GpPen/GpBrush/GpPath/GpFont/GpStringFormat`）配 RAII wrapper。
- 颜色是 ARGB `u32`；坐标有整型/浮点两套 API，自绘用浮点版更平滑。

## 4. 后端注入方式

`flexui` 门面 crate 用 `cfg` 选择：

```rust
#[cfg(target_os = "macos")]
pub(crate) type ActiveBackend = flexui_macos::MacBackend;
#[cfg(target_os = "windows")]
pub(crate) type ActiveBackend = flexui_windows::WinBackend;
```

上层 API 只与 `ActiveBackend: Backend` 打交道，编译期零成本选型。

## 5. 两平台差异需特别封装的点（清单）

1. **坐标 Y 方向**（macOS 翻转）。
2. **双缓冲**（Windows 要手动，macOS 自动）。
3. **文本度量差异**（字体、字距、抗锯齿策略不同 → 需统一度量口径，必要时做校准）。
4. **DPI 时机**（Windows 运行时可能变 `WM_DPICHANGED`）。
5. **事件坐标单位**（都要换算成逻辑像素）。
6. **主循环所有权**（`NSApp run` vs 自写 `GetMessage` 循环）。
