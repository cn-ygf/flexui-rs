# flexui-rs 控件与样式模型（细节需求）

本文把用户给定的控件级细节需求，落成可实现的模型。对应需求：状态机、样式、
容器嵌套、事件穿透、基础/扩展控件、radio group、tabbox/tabbar。

## 1. 状态机（需求 1、2）

### 1.1 基础状态（4 种）
`Normal`（普通）、`Hot`（悬停/hover）、`Pushed`（按下）、`Disabled`（禁用）。

### 1.2 焦点维度（× 2）
上述每种状态再叠加 **是否 focus**，共 **4 × 2 = 8 个样式槽**：

```
Normal / Normal+Focus
Hot    / Hot+Focus
Pushed / Pushed+Focus
Disabled / Disabled+Focus
```

用「基础状态 + focus 布尔」正交表示，而非枚举 8 个平铺值：

```rust
/// 基础状态，优先级 Disabled > Pushed > Hot > Normal
pub enum BaseState { Normal, Hot, Pushed, Disabled }

/// 控件当前的完整视觉状态
pub struct VisualState { pub base: BaseState, pub focused: bool }
```

### 1.3 状态解析与回退（关键规则）
控件的运行时状态由输入推导，样式按**回退链**取：

- **基础状态优先级**：`Disabled` 最高（禁用时忽略 hover/pressed）→ `Pushed` → `Hot` → `Normal`。
- **focus 是修饰维度**：先算基础状态，再看是否 focus。
- **样式回退**：`(base, focused=true)` 未定义 → 退到 `(base, focused=false)` → 再退到 `Normal`。
  单个样式字段缺省时，继承自 `Normal` 槽（见第 2 节字段级回退）。

## 2. 分状态样式（需求 3）

每个样式槽是一份 `StyleSpec`，**所有字段可缺省**，缺省则字段级继承 `Normal`：

```rust
pub struct StyleSpec {
    pub rect:          Option<RectSpec>,   // 位置/尺寸参数（相对父，或由布局决定）
    pub bg_color:      Option<Color>,      // 背景颜色
    pub fg_color:      Option<Color>,      // 前景颜色（文字/图标）
    pub bg_image:      Option<ImageRef>,   // 背景图片
    pub fg_image:      Option<ImageRef>,   // 前景图片
    pub border_color:  Option<Color>,      // 边框颜色
    pub border_width:  Option<f32>,        // 边框大小
    pub corner_radius: Option<Corners>,    // 圆角参数（四角可独立）
}

pub struct Corners { pub tl: f32, pub tr: f32, pub br: f32, pub bl: f32 }
pub struct RectSpec { /* x/y/w/h，支持像素/百分比/auto */ }
pub struct ImageRef { /* 路径或资源 id + 九宫格拉伸参数(可选) */ }
```

控件持有一张 `StyleSet`：8 个槽的稀疏表。绘制时：
1. 由 `VisualState` 解析出生效槽（含回退）。
2. 逐字段用「生效槽 → Normal」补全，得到最终 `ResolvedStyle`。
3. 后端 `Canvas` 按 ResolvedStyle 画：背景色 → 背景图 → 边框（含圆角）→ 前景图 → 前景（文字）。

> **图片资源**：一期先支持 PNG/位图从文件/内存加载；由后端解码（macOS `NSImage`/CGImage、
> Windows GDI+ `GdipCreateBitmapFromFile`/`FromStream`）。九宫格拉伸列为增强项。

## 3. 容器体系（需求 4、5）

分两类容器能力：

### 3.1 单子容器（需求 4）——所有控件的基类
**每个控件本身就是容器，可嵌套 0 或 1 个子控件**（类似装饰器/包裹）。
这让 Button 里能放一个 Label、Label 里能放一个 Image 等自由组合。

```rust
pub trait Widget {
    fn state(&self) -> &WidgetState;             // 状态机 + StyleSet
    fn set_child(&mut self, child: Box<dyn Widget>); // 单子槽（0..1）
    fn layout(&mut self, avail: Size) -> Size;   // 求尺寸/摆放
    fn paint(&self, cv: &mut dyn Canvas);        // 自绘
    fn on_event(&mut self, ev: &Event) -> EventFlow;
}
```

### 3.2 多子容器（需求 5）——Box / VBox / HBox
- **Box**：层叠容器，多个子控件按各自 rect 叠放（类似 duilib Box / 绝对/覆盖）。
- **VBox**：纵向 Flex 排列多个子控件。
- **HBox**：横向 Flex 排列多个子控件。

三者实现同一 `MultiChildContainer` 能力（`children: Vec<Box<dyn Widget>>`），
排列策略走第 `01/04-架构与布局` 的 Flex 引擎；Box 方向=none（叠放）。

> 命名与 duilib 对齐（Box/VBox/HBox），降低 XML 布局迁移成本。

## 4. 事件穿透（需求 6）

每个控件带命中测试策略，决定事件是否被它「吃掉」：

```rust
pub enum HitPolicy {
    Solid,       // 不穿透：命中即消费，事件不再下传到下层
    Transparent, // 穿透：自身不接收，事件穿过去给下层/父级兄弟
}
```

- 命中测试时若控件为 `Transparent`，跳过它继续找下层目标。
- 对纯装饰控件（背景板、遮罩层的非交互区）非常有用。
- 默认交互控件（Button 等）为 `Solid`，纯展示容器可配 `Transparent`。

## 5. 基础控件（需求 7）

一期基础控件清单（都基于第 3.1 单子容器 + 第 1/2 状态样式）：

| 控件 | 说明 |
| ---- | ---- |
| `Control` | 抽象基类：状态机 + StyleSet + 单子槽（其余控件继承它） |
| `Label` | 文本显示（对齐/省略/换行） |
| `Button` | 按钮，走完整 4×2 状态 |
| `Image` | 图片显示控件 |
| `Edit` | 单行文本输入（基础版，IME 延后） |
| `CheckBox` | 勾选框（selected 态叠加到状态机） |
| `Progress`/`Slider` | 进度/滑块（可延后） |

## 6. 扩展控件（需求 8、9）

### 6.1 Radio + Group（需求 8）
- `Radio` 是带 `selected` 的控件；同一 `group` 内**互斥单选**。
- 用 `group_id` 关联；一个 group 维护「当前选中项」，切换时旧项取消选中并重绘。

```rust
pub struct RadioGroup { id: GroupId, selected: Option<WidgetId> }
```

### 6.2 TabBox（需求 9）
- `TabBox` 是多页容器，同时只显示一个「当前页」子控件（selected index）。
- 切换页 = 改 selected index → 隐藏旧页、显示新页、重绘。

### 6.3 Radio 关联 TabBox = Tabbar（需求 9）
- 一组 `Radio`（同 group）与一个 `TabBox` 绑定：radio 的选中项索引 → 驱动 tabbox 当前页。
- 形成常见的「顶部标签 + 下方内容」的 **Tabbar**。
- 绑定用「名字/索引关联」表达（XML 里 `tabbox` 属性 + radio 的 `tab_index`，
  代码里 `tabbar.bind(group, tabbox)`），底层是 group 选中变化事件 → 设置 tabbox 页。

- 上述状态、样式、容器、穿透、分组、tabbox 绑定，都要能在 **代码 API** 与
